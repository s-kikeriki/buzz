# Internationalisation (desktop)

The desktop app renders English, German, and a generated pseudo-locale from
message catalogues. This document is the conversion recipe: a screen converted
by following it needs no further decisions.

Library: **Lingui v6**. Chosen because extraction — not rendering — is the hard
part of this job, and Lingui's CLI can fail a build on a string that never
reached a catalogue. That mechanism is what `pnpm check:i18n` is built on.

---

## Layout

| Path | What it is |
|------|------------|
| `desktop/lingui.config.ts` | Locales, catalogue paths, PO formatter |
| `desktop/src/locales/<locale>/messages.po` | Committed catalogues |
| `desktop/src/shared/i18n/i18n.ts` | Catalogue activation, generation fencing |
| `desktop/src/shared/i18n/AppI18nProvider.tsx` | Gates render on first activation |
| `desktop/src/shared/lib/localePreference.ts` | Persisted choice (same shape as `fontSizePreference`) |
| `desktop/src/shared/branding/brand.ts` | `BRAND.productName` — the only product name |
| `desktop/scripts/vite-plugin-lingui-macro.mjs` | Macro transform (see *Build* below) |

## The four shapes

Almost every string is one of these. Pick by where the string lives, not by
what it says.

### 1. Text inside JSX — `<Trans>`

```tsx
import { Trans } from "@lingui/react/macro";

<p>Accent color</p>
<p><Trans>Accent color</Trans></p>          // ✅
```

Inline markup stays inside the element — do not split a sentence into
fragments, because translators need the whole clause to reorder it:

```tsx
<Trans>
  Read the <a href="/docs">documentation</a> first.
</Trans>
```

### 2. A string-typed prop — the `` t`` `` macro

```tsx
import { useLingui } from "@lingui/react/macro";

const { t } = useLingui();

<SegmentedControl legend="Font size" />
<SegmentedControl legend={t`Font size`} />   // ✅
```

Applies to every prop a person reads or hears: `aria-label`, `title`,
`placeholder`, `alt`, `legend`, `label`, `description`, `resetLabel`. The CI
guard knows this list.

### 3. A module-level table — `` msg`` `` plus a render-time lookup

This is the one that bites. A table at module scope is built **once at import
time**, before any catalogue is active, and never rebuilds when the locale
changes. A plain string there is frozen in whatever locale booted.

```tsx
import { msg } from "@lingui/core/macro";
import type { MessageDescriptor } from "@lingui/core";

const FONT_SIZE_OPTIONS: readonly { value: FontSize; label: MessageDescriptor }[] = [
  { value: "smaller", label: msg`Smaller` },   // ✅ descriptor, not string
];

// …resolved per render:
const { i18n } = useLingui();
const options = React.useMemo(
  () => FONT_SIZE_OPTIONS.map(({ value, label }) => ({ value, label: i18n._(label) })),
  [i18n],
);
```

`AppearanceSettingsControls.tsx` has a reusable `useSegmentOptions` helper for
exactly this.

### 4. The product name — never a literal

```tsx
import { BRAND } from "@/shared/branding/brand";

const { productName } = BRAND;   // destructure at module scope

<Trans>Choose the highlight color used throughout {productName}.</Trans>
```

Two reasons for the destructure: a member expression (`BRAND.productName`)
makes the macro emit a positional `{0}` placeholder, which translators cannot
place correctly in German word order; a bare identifier emits `{productName}`.

`BRAND.productName` reads `VITE_BUZZ_PRODUCT_NAME` at build time and falls back
to `Buzz`. A per-organisation build sets that env var — the catalogue entry
never changes, so rebranding costs no retranslation.

## What is *not* copy

Out of scope by design, not by omission:

- `className`, `data-testid`, `id`, `href` — markup and data.
- Closed-union tokens the renderer switches on. `typeLabel="link"` on a link
  preview is a type, not text; translating it is a type error.
- Sample persona data in decorative previews (`author="Maya"`, `"9:41"`).
  Names are names.
- Language names in the picker. Each language is listed in its own language
  (`English`, `Deutsch`) so someone stranded in a locale they cannot read can
  still find the way out.

## Converting a screen

1. Convert every string using the four shapes above.
2. `cd desktop && pnpm i18n:extract`
3. Translate the new German entries in `src/locales/de/messages.po`.
   `pseudo` is generated — never edit it.
4. Add the converted files to `CONVERTED_FILES` in
   `desktop/scripts/check-i18n-coverage.mjs`. **In the same change.** That list
   is the ratchet; a screen that is not in it has no regression protection.
5. If the screen lives inside a file shared with unconverted screens, move it
   to its own file first — the guard works per file.
6. `pnpm check:i18n && pnpm typecheck && pnpm test`

## The guards

Three, each verified to fail when it should:

| Command | Catches |
|---------|---------|
| `pnpm check:i18n` → `check-i18n-coverage.mjs` | A hardcoded JSX text node or copy-bearing prop in a converted file |
| `pnpm check:i18n` → `check-i18n-catalogs.mjs` | Catalogues out of sync with the source; empty source translations |
| `tests/e2e/i18n-appearance.spec.ts` | Untranslated copy at runtime, and German/pseudo overflow |

### Why the catalogue guard matters more than it looks

When a `<Trans>` has no catalogue entry, Lingui falls back to the message
**id**. Production builds strip the `message` property, so the id is the
compiled hash: the UI renders `2fQh92` where the label belongs. It looks like
data corruption, the source still reads fine in review, and neither TypeScript
nor Biome can see it. This was hit for real while building this; the guard
exists because of it.

### How overflow actually fails

Measured, not assumed. A segment label too long for its column does **not**
widen the button. The text wraps, the button grows taller (28px → 48px at three
lines), and the `h-8 overflow-hidden` fieldset clips it vertically. So the
signal is the fieldset's `scrollHeight`, not any button's `scrollWidth`. The
spec checks both axes so a future `whitespace-nowrap` is still caught.

German runs ~30% longer than English; `pseudo` pads further still and is the
stress input.

## Build

The macro transform runs as its own Vite plugin
(`scripts/vite-plugin-lingui-macro.mjs`), **not** inside `react()`.

This app is on Vite 8 with `@vitejs/plugin-react` v6, which transforms through
Oxc and has no `babel` option at all — its `Options` interface is `include`,
`exclude`, `jsxImportSource`, `jsxRuntime`, `reactRefreshHost`. Passing
`babel: { plugins: [...] }` there is accepted silently and does nothing: the
macros never expand, `useLingui()` compiles to `void 0`, and every converted
screen throws at runtime with a green build. The dedicated plugin runs with
`enforce: "pre"` and only parses files that actually import a Lingui macro.

If a future Vite upgrade restores Babel inside `react()`, this plugin can be
deleted — but verify by grepping the built bundle for a compiled id
(`id:"lBdPxu"`) rather than trusting the build to fail.

## Adding a locale

1. Add it to `locales` in `desktop/lingui.config.ts`.
2. Add it to `AppLocale` and `APP_LOCALES` in `shared/lib/localePreference.ts`.
3. Add its endonym to `LOCALE_ENDONYMS` in
   `features/settings/ui/LanguageSettingsControl.tsx`.
4. `pnpm i18n:extract`, translate, commit.
